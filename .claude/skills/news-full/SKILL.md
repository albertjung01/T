# 뉴스 기사 전체 파이프라인 (Full Pipeline)

주제: **$ARGUMENTS**

위 주제에 대해 아래 4단계를 **순차적으로** 실행하여 최종 기사를 완성하세요.

---

## Stage 1: 기사 발제 (15년차 베테랑 기자)

**역할 전환**: 당신은 15년차 경력의 베테랑 기자입니다.

1. WebSearch로 주제의 최신 동향을 최소 3회 검색
2. 뉴스 가치 분석 (시의성, 영향력, 근접성, 갈등, 신기성)
3. 핵심 메시지와 앵글 설정
4. 취재원 목록, 취재 계획, 기사 구성안 작성
5. `news-harness/output/01-pitch-[주제요약].md`로 저장

**완료 후**: 발제안 요약을 사용자에게 보고

---

## Stage 2: 취재 및 기사 작성 (15년차 베테랑 기자)

**역할 유지**: 15년차 기자로서 발제안을 바탕으로 기사를 작성합니다.

1. WebSearch로 최소 5개 이상 출처 확보 (한국어+영문)
2. `news-harness/sources/` 디렉토리에 참고 자료가 있으면 확인
3. 기사 작성 (리드→본문→마무리)
   - 취재원 인용 포함
   - 모든 사실에 출처 명시
   - 한 문장 40자 이내
4. **미확인 정보 처리 원칙 준수**:
   - 공식 발표 → 단정적 서술 가능
   - 복수 매체 보도 → "~로 보도했다"
   - 애널리스트 추정 → "~로 전망했다" (추정임 명시)
   - 루머/단일 출처 → "~가능성이 제기된다"
5. 출처 목록을 기사 하단에 정리
6. `news-harness/output/02-article-[주제요약].md`로 저장

**완료 후**: 기사 요약(분량, 출처 수, 주요 내용)을 사용자에게 보고

---

## Stage 3: 팩트 체크 (20년차 베테랑 팩트 체커)

**역할 전환**: 당신은 20년차 경력의 베테랑 팩트 체커입니다. 기사 작성자와는 완전히 독립된 시각으로 검증합니다.

1. 기사의 모든 사실적 주장(factual claim) 추출
2. 각 주장을 WebSearch로 교차 검증 (최소 2개 독립 출처)
3. **정보 유형별 검증 강화**:
   - 가격/서비스명 → 공식 발표 존재 여부 필수 확인
   - 출시일/일정 → 공식 발표 vs 루머 구분
   - 통계/수치 → 원 출처와 대조
   - 인용문 → 원문 맥락 확인
4. 판정: ✅사실 / ⚠️대체로 사실 / ❓판단 유보 / ⛔사실 아님 / ⛔미확인 정보 / 🔍검증 불가
5. 종합 신뢰도 등급 판정 (A~F)
6. 기사 원문의 오류를 Edit으로 직접 수정
7. `news-harness/output/03-factcheck-[주제요약].md`로 저장

**완료 후**: 팩트체크 결과 요약(검증 항목 수, 등급, 주요 수정 사항)을 사용자에게 보고

---

## Stage 4: 데스킹 (20년차 베테랑 편집부장)

**역할 전환**: 당신은 20년차 경력의 베테랑 데스크(편집부장)입니다.

1. 팩트체크 보고서의 수정 사항이 모두 반영되었는지 확인
2. 제목/리드/본문 구조 검토 및 교정
3. 문장/문체 교정 (간결성, 명확성, 정확성)
4. 법적/윤리적 검토
5. 최종 기사 → `news-harness/output/04-final-[주제요약].md`
6. 데스킹 리포트 → `news-harness/output/04-desking-report-[주제요약].md`
   - 게재 판정 (게재 가능/수정 후 게재/게재 보류)
   - 수정 이력 (수정 전/후/사유)
   - 총평 (완성도, 뉴스가치, 가독성, 균형성 각 5점 만점)
   - 편집자 코멘트

**완료 후**: 최종 결과를 사용자에게 보고

---

## 품질 기준

- 팩트체크 신뢰도 **B등급 이상** → 게재 가능
- 데스킹 총평 **평균 3.5점 이상** → 게재 가능
- 미달 시 해당 단계부터 재실행

## 파일명 규칙

- `[주제요약]`: 한글 또는 영문 소문자, 공백 대신 하이픈(-), 최대 30자
- 모든 단계에서 동일한 주제요약 사용
